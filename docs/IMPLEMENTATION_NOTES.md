# Примечания к реализации

## Принятые решения
1. Авторизация построена на случайном opaque session token в HttpOnly cookie. В БД сохраняется SHA-256 от токена, а не исходный токен.
2. Для изменения состояния через HTTP используется CSRF-токен из `/api/auth/me` и заголовок `X-CSRF-Token`.
3. Пароли хешируются Argon2id. Минимальная длина — 12 символов.
4. Сообщения сохраняются в PostgreSQL. WebSocket используется для доставки создания, редактирования, удаления, реакций и вложений; между экземплярами backend события передаются через Redis Pub/Sub.
5. Redis используется для rate limiting регистрации и входа (счётчики по IP с TTL), Redis Pub/Sub для межпроцессной доставки событий и health check. Сессии и сообщения хранятся в PostgreSQL.
6. Nginx — единая точка входа: проксирует `/api`, `/ws`, `/metrics`, `/health` и Next.js.
7. TanStack Query хранит серверное состояние. Redux из исходного примера заменён, так как данные пользователя и сообщений приходят с API и удобнее кэшируются Query.

## Новые функции
- Аватар: `POST /api/auth/avatar` (multipart, поле `avatar`, максимум 5 МБ); файлы доступны как публичные изображения профиля.
- Вложения: `POST /api/conversations/:id/files` (multipart, поле `file`, максимум 15 МБ); скачивание через `GET /api/files/:id` требует авторизации и членства в диалоге.
- Личные диалоги: `GET /api/users?q=`, `GET /api/conversations`, `POST /api/conversations/direct`.
- История: `GET /api/conversations/:id/messages?limit=30&before_id=...`.
- Редактирование: `PUT /api/messages/:id`; удаление: `DELETE /api/messages/:id`.
- Реакции toggle: `POST /api/messages/:id/reactions` с `{ "emoji": "👍" }`.
- Redis Pub/Sub: канал `redchat:chat:events`; каждый event envelope содержит список получателей и payload, который отправляется только локальным соединениям этих пользователей.
- WebSocket Origin: точное совпадение `Origin` с одним из значений `ALLOWED_ORIGINS`; отсутствующий и посторонний Origin запрещён.

## Что проверить вручную
- Регистрация с паролем короче 12 символов отклоняется.
- Повторная регистрация с тем же username возвращает 409.
- Неавторизованный пользователь перенаправляется на `/login`.
- Сообщения появляются в двух открытых браузерах без перезагрузки.
- Удаление чужого сообщения невозможно.
- После выхода защищённые endpoints возвращают 401.

## Ограничения первой версии
- Личные диалоги реализованы как диалоги один-на-один; групповые чаты не входят в эту версию.
- Вложения сохраняются в Docker volume; для нескольких серверов/облачного развёртывания стоит заменить локальное хранилище на S3-совместимое object storage.
- Redis Pub/Sub работает между backend-репликами, но сообщения как источник истины остаются в PostgreSQL.
- Для production задайте HTTPS, корректный `ALLOWED_ORIGINS` и отдельные сложные секреты.
- Кнопка подгрузки старых сообщений реализует cursor pagination по `before_id`; автоподгрузку по IntersectionObserver можно добавить как UX-улучшение.
